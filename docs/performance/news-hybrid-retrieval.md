# N4-K 混合检索与 RRF 离线评估

## 范围

基线是 N4-J 主线 a519d3f 的实际 ArticleIndex.search（英文 FTS5/BM25，中文与混合词字面路径）。新增独立的字符标题检索器：汉字二元、ASCII 字母/数字三元字符 gram（短词用可用长度），NFKC/小写归一化，按 IDF 加权的查询 gram 覆盖率排序，固定阈值 0.5。它是近似字面匹配，不是 Embedding、语义模型、ANN 或持久化向量索引。

RRF 使用两通道各前 20 个候选，按文章 ID 去重，每通道重复 ID 仅计一次。得分为各通道 1/(60+rank) 之和，rank 从 1 开始，稳定 ID 打破平局，取前 5。无外部调用、无新增运行时依赖、无数据库迁移及公共 API 变化。

## 数据与复现

`pnpm performance:hybrid-search`（可重定向 JSON）使用 N4-H 的 73 条报道，另固定 21 个查询，包括错拼、混合语种、版本、事件意图和 4 个无答案查询。45 个查询-报道相关标签是助手初标，既未独立人工核验，也不是独立报道保留集；与 N4-J 字面查询的标签定义不同。候选深度 20、返回深度 5；20 轮，每方法 420 次热查询。Linux / Node 22.23.4 / pnpm 12.21.0；SQLite 内存库，字符通道内存预构建，未计入建库、序列化或 HTTP 成本。nDCG@5、MRR@5 和宏召回仅对有答案查询求均值，微精确率以实际返回数为分母；无答案查询单列。全量查询及结果见脚本 JSON。

## 准入结论

完成离线实验交付，保留现有生产检索路径。先做独立相关性标注和分层保留集，确定版本误命中、跨语种、无答案及精确率下限；同时对实际规模的索引构建、内存、查询成本和增量更新做对照。只有证明候选通道和融合相对最佳单通道存在独立增益且满足延迟/精确率目标，才进入可选 API 或 Embedding/ANN 设计，未经评估不引入付费服务。此结论不表示 RRF 在其他数据集无价值。
