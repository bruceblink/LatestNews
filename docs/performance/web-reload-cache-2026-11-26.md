# Web 短期重载缓存验收（2026-11-26）

## 目标及边界

用户要求避免浏览器短时间内反复打开或刷新页面时重新生成洞察与查询新闻。基线为 2c006e3（N4-P3 诊断工具合并后），本切片仅调整 Web 读取缓存与目录启动时序；不改变服务端采集、索引、数据库和生产调度，不扩大同步能力。

## 行为

- 完整洞察快照新鲜期 3 分钟；含可用报道的部分结果为 30 秒，且不能替换同键仍可用的完整快照。全失败结果不持久化。查询键包含 API 地址、全部筛选与阅读/隐藏条件，存储中仅保存键的 SHA-256 摘要，不保存原始查询键、凭据或请求头。
- Feed 新鲜期 2 分钟，使用既有离线快照的保存时间，并只将同 API 地址且校验通过的完整快照用于在线恢复。相对时间范围使用稳定语义键，实际请求和本地筛选重新计算截止时间。旧离线数据仍按既有规则显示。
- 来源卡片保留现有 1/2/4 分钟新鲜期，失败来源为 5 分钟；来源详情条目为 2 分钟、关联 Feed 为 3 分钟、支持持久化的元数据为 10 分钟。动态来源详情元数据仍实时解析。
- 已知同 API 地址的运行目录在 3 分钟内直接恢复；过期目录先恢复，再后台校验。首次、旧格式或无匹配缓存仍走有界启动流程。
- 通用新闻快照超过新鲜期先显示上次结果并正常后台请求，最多恢复 30 分钟内的快照。存储版本化、最多 32 项、整体 512 Ki UTF-16 码元、单项 128 Ki 码元；坏数据、超限或禁用存储、摘要能力不可用时走正常查询。手动查询不受新鲜期限制，清缓存刷新保留已有服务端语义。恢复不会延长原始保存时间。
- 新增持久化仅用于浏览器，不用于尚未建立可信 API 身份的 Electron 渲染器；登录、健康状态和归档查询仍走原有路径。缓存为本机展示数据，并非账户隔离或授权机制。退出登录清除新增通用缓存，并阻止旧代恢复与写入。

## 浏览器实测

相同宿主、Chromium、两份静态生产构建，回环 HTTP 夹具固定目录延迟 300 ms、洞察延迟 1,200 ms；每版本三个独立浏览器上下文，先冷打开再立即刷新。静态资产 no-store，阻止 service worker 和外网请求。记录导航至第一条报道可见的墙钟时延，以及显示后 250 ms 内启动的两个目标 API 请求。测试数据为合成新闻，不是生产流量。

| 指标 | 基线 | 候选 |
| --- | ---: | ---: |
| 刷新首条报道可见（第 1 轮） | 1879.8 ms | 196.3 ms |
| 第 2 轮 | 1878.4 ms | 197.4 ms |
| 第 3 轮 | 1876.1 ms | 195.1 ms |
| 中位数 | 1878.4 ms | 196.3 ms |
| 每次刷新目录请求数 | 1 | 0 |
| 每次刷新洞察请求数 | 1 | 0 |

刷新时延中位数减少约 89.5%。首次打开仍需要网络请求；首轮冷启动受宿主状态影响，不宣称冷启动提升或生产 SLO。完整样本见 [JSON](web-reload-cache-2026-11-26.json)。

117 个 Vitest 文件、652 项通过；Chromium 全量 87 项通过（含 PWA 离线恢复、缓存失效、显式刷新、部分结果与筛选变化）；lint、三端类型检查、静态 Web 生产构建通过。
