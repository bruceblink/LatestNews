# N4-P3 在线写入与最终审核锁（2026-11-26）

基线 e619d1d（#38 变基合并）。本轮实现在线回放优化、可复现实验和阶段性验收。正式 1800 秒长测尚未完成，不宣称生产 D1 或完整 N4-P3 准入通过。

## 方法

- 隔离 Linux x64 / AMD EPYC 8 核、Node 22.23.4、SQLite 3.53.4、better-sqlite3 13.0.3。真实临时文件库、DELETE journal、synchronous=FULL、busy_timeout=5000ms；没有改用 WAL 或降低持久性。
- 每轮重新构造已审核的 1k/10k/100k 文章及映射。一个进程执行 Cache.runArticleMaintenance(5)，两个独立进程/连接分别执行 Cache.set（30 条快照，四个循环来源）和 ArticleIndex.search（固定唯一命中）。每快照含唯一标记与 29 条固定 URL 的新观测。最终逐条比对标记、最新标题、来源、缓存、计数、完整 FTS 审核与 pending/untracked=0。
- 绝对时钟限速，不补发逾期请求；分别报告预定、完成、失败、跳过、重试。P50/P95/P99 是已完成操作从开始到结束的时延，另记调度迟滞；跳过不能算成功。重建窗口为 begin 至维护者观察 ready+verified，有轮询误差，不是纯 SQL 时间。
- 测 BEGIN IMMEDIATE 调用至回调进入的获取锁耗时（含驱动调用开销），回调与 COMMIT/ROLLBACK 尾部另计，held 为回调进入至事务返回。非事务 SQL 等待不单独分离；BUSY/LOCKED 计数分别记录，不能将全部事务尾部当作 fsync。event-loop delay、RSS 与队列年龄为采样，不保证瞬时峰值。
- 初轮 4 快照/s + 5 读/s 的 100k 无重建校准因维护不可用失败，未取得完整结果。2 快照/s + 5 读/s、12 秒的未优化基线完成 7/24 快照、跳过 17、维护 BEGIN IMMEDIATE 超时 2 次；已确认观测最终一致。逐条 FTS 更新反复扫描未索引 article_key；复用既有 D1 集合式写入后同配置完成 24/24、维护锁超时 0，检索跳过 1。该探索对照只有一轮、实际完成负载不同，不用 P95 比值作因果结论。
- 正式速率由优化后的无重建校准确定：1 快照/s、2 读/s，100k 15 秒完成 15/15 与 30/30，写 P95 187.133ms、读 P95 9.295ms，零失败/跳过/锁超时。
- 每个 size/page 三轮，50/200 交替，100 后续补测。100k 最终 45 秒窗口，每轮一次重建；1k 8 秒每 2 秒重建、10k 12 秒每 4 秒重建。早期 100k 30 秒组的 50 键最终审核均落在输入窗口之后、200 键在输入内，不能据此判断公平的写延迟门槛，不混入最终矩阵。未随机化，低样本分位数不稳定。

## 实现决策

1. 仅为持有维护租约的 SQLite journal 回放启用既有 set-based SQL：每个最多 30 条分片，一个文章/来源/待修事务和一个 FTS 事务；保留租约 fencing、canonical URL 身份、观测时间保护、journal/checkpoint 和完整 FTS 审核。直接 ArticleIndex SQLite 写入保留逐条路径；D1 SQL 不变。测试覆盖重复 URL 的最后观测、候选键碰撞、旧观测、30 条批次两事务、事务回滚和重试。
2. 在线 Cache.runArticleMaintenance 的 SQLite build page 改为 100；直接 ArticleIndex rebuild/continue 默认仍为 200，D1 build 50、清除 200、pending 50 不变。100 对 50 在三种规模的恢复及写 P95 中位数均改善；100k 恢复耗时减少约 38.4%，写 P95 降低约 2.4%，三轮未跳过，最差 P99 低于 200。200 恢复更快且最终 45 秒写 P95 中位数也符合 +20% 候选线，但尾延迟与跳过较差。保守选择 100，不宣称普适最优或生产 SLO。
3. 50/100/200 仅为受限内部实验参数，非法值拒绝，不新增公开配置项。完整原子审核仍在，在线软预算不能抢占已运行 SQL。显式全量重建建议在维护窗口执行。若候选出现持续积压或写入尾延迟异常，回退 SQLite 在线页大小与回放策略，保留 durable journal/证据表；D1 不变。

## 90 秒重复重建诊断（未通过负载准入）

单独执行 100k、100 键、1 快照/s、2 检索/s、每 30 秒尝试开始新重建、90 秒输入。完成两次恢复（61.877s、49.220s），输入停止至最终收敛约 21.827s。45/90 写入、77/180 读取实际完成，跳过 45/103；没有操作失败或重试，最终 100161 篇及来源、全部已确认标记一致，FTS verified，pending/untracked 均为 0。写入 P95 459.906ms、P99 13462.400ms，读取 P95 6533.383ms、P99 13316.629ms。写/读 event-loop max 分别 13497.270/13463.716ms，写 BEGIN 获取最大 429.907ms。维护采样最多 2 个 journal、127 个 FTS pending、最老 6516ms。该次通过隔离后台进程启动，fixture 准备明显变慢；无法隔离宿主调度、I/O、JS 执行与负载原因，不能把停顿归因于单一因素，也不能据此宣称稳定吞吐。旧脚本 RESULT passed 仅表示正确性，现改为跳过时 incomplete-load、exit 2；错误 exit 1。完整记录保留，不计入 27 轮矩阵。正式长测前应先稳定运行环境，查明停顿并复测。
