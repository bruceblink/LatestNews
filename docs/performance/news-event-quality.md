# N4-D 新闻事件聚合质量

## 目标

本切片改进 `shared/news-insights.ts` 的事件匹配。匹配过程使用以下条件：

- URL 规范化结果相同。
- 标题规范化结果相同。
- 共享实体或版本词，并且至少共享两个非通用词。
- 版本号、事件类型和发布时间窗口没有冲突。

事件组在合并前再次检查两个组的稳定锚点。该检查阻止单个弱关键词把两个独立事件连接起来。

## 标注样本

测试数据位于 `test/fixtures/news-event-labeled-pairs.ts`，共有 200 对样本：

- 100 对同一事件，覆盖中文和英文实体、版本号以及 0 到 2 天的发布时间差。
- 100 对不同事件，覆盖不同实体、不同版本、发布与安全事件类型冲突以及超过 7 天的时间差。

样本是确定性合成数据。它用于回归聚合规则，不代表公网新闻质量。

## 结果

在 Node 22.23.4、pnpm 12.21.0 和当前提交上运行：

```bash
pnpm exec vitest -c vitest.config.ts run test/news-insights.test.ts
```

结果为 200 对样本全部通过，Precision 为 1.00，Recall 为 1.00。该结果只说明标注样本中的规则行为符合预期，不能替代真实来源的人工抽样评估。

## 稳定标识和兼容性

`TopicEvent.id` 保留原有的 URL 集合哈希，用于兼容旧客户端。共享聚类算法使用最早报道的规范化 URL 或标题指纹生成候选 `eventId`。补入更早报道、隐藏报道或改变来源范围时，该候选可能改变。

服务端基于现有 `articles.event_id` 协调标识。若组内只有一个已持久化 ID，则复用该 ID 并为未关联文章赋值；若没有已持久化 ID，则使用本次候选。已有两个及以上 ID 时不覆盖、不自动合并，也不为新成员赋值，此时返回候选 ID。没有索引或索引访问失败时同样返回候选 ID。无冲突时协调结果用于洞察响应和文章搜索。旧 `id`、聚类规则及 API 字段保持不变。

赋值通过单条 SQLite 语句完成，使用 JSON 参数限制绑定数量。该切片不增加数据库表或迁移。仅对存在共同索引文章且无 ID 冲突的组保证复用；无共同文章的组、已存在的冲突、候选哈希冲突及客户端独立离线聚类不保证全局稳定。后续仍需真实来源标注、独立事件注册表及冲突处理策略。目标 D1 环境需另行验收。
