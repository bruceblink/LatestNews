# 桌面本地采集持久缓存

日期：2026-10-24。基于桌面远端到本地采集回退切片 `d4b9cfc`。本切片保存桌面本地采集结果，并在后续采集失败时恢复最近一次成功结果。

## 行为

- Electron 主进程将本地插件成功返回的非空新闻条目写入 `<userData>/crawler-cache.json`。
- 本地插件返回有效空结果时，当前请求仍返回 `empty`，缓存保留上一次非空结果。
- 本地插件抛出异常时，主进程读取该来源的缓存。缓存年龄不足来源刷新间隔的两倍时返回 `degraded-cache`；达到两倍时返回 `stale-cache`。
- 没有可用缓存时保留原采集错误。缓存写入失败只记录警告，当前成功采集结果仍返回给页面。

## 资源边界与文件安全

- 单文件最多 2 MiB，最多 64 个来源，每个来源最多 100 条新闻。
- 只接受长度不超过 128 且符合来源 ID 字符范围的 key。缓存条目只保存具备 ID、标题和 URL 的新闻数据。
- 写入先创建同目录临时文件，再重命名替换目标文件。失败时删除临时文件。进程内写入排队执行，避免并发覆盖其他来源的更新。
- 文件不存在、格式错误、版本不支持、记录无效或文件超限时，按空缓存处理。缓存属于桌面 `userData`，不传到 Web API 或 SyncHub。

## 实现

- `electron/crawler-cache.ts` 负责加载、校验、裁剪、序列化和原子写入。
- `electron/crawler-plugin-provider.ts` 负责成功写缓存，以及采集失败后的缓存状态判定。
- `electron/main.ts` 仍只通过主进程 IPC 返回本地采集结果；缓存文件路径不接受渲染进程输入。

## 验证结果

- `pnpm check`：通过，74 个测试文件、360 个测试。
- 定向缓存测试：通过，覆盖磁盘重载、格式损坏、文件超限、来源和条目上限及并发写入。
- 定向 provider 测试：通过，覆盖正常结果、空结果保留旧缓存、`degraded-cache` 和 `stale-cache`。
- `pnpm typecheck:electron`、`pnpm electron:build`：通过。
- 本切片没有修改界面。真实窗口交互验收不适用；provider 测试使用可控采集结果，不代表公网来源采集通过。

## 回退边界

删除 `electron/crawler-cache.ts`，恢复 `electron/crawler-plugin-provider.ts` 的无缓存返回路径，并移除对应测试和本节文档，即可回退。本切片不改变 Web API、数据库、来源 ID、插件包格式或远端回退规则。
