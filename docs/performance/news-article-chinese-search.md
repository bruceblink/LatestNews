# N4-J 中文标题检索与相关性排序

## 方案与边界

保留英文 FTS5/BM25，中文或中英混合查询走字面子串匹配，避免 unicode61 只能命中完整词而遗漏其他中文标题。空白分隔词必须全部出现在同一标题或规范 URL 中；百分号、下划线按字面字符匹配，不是通配符。ASCII 大小写不敏感。标题完整相等、连续短语、分散词命中、仅 URL 命中依次优先；同等级按发布时间降序、文章主键排序。API q 去除首尾空白后限 256 个 UTF-16 code unit；仍使用原 searchMode=like，未改变字段结构。未新增数据库索引或依赖。

中文路径是 SQLite 字面扫描，不是词典分词、语义检索或专用倒排索引。URL 按已存储规范 URL（可能含百分号编码）匹配，不能承诺对解码 URL 搜索。英文正常查询仍用 BM25，失败或无结果时字面回退。查询中的短 ASCII 子串可能命中品牌或域名。未验证大规模生产 D1 扫描成本；上线后须测真实数据量，必要时再引入倒排或 trigram 索引。

## 实测对照

固定 N4-H 的 73 条报道与 15 个字面标题初标查询，limit=10，20 轮共 300 次查询，Linux / Node 22.23.4 / pnpm 12.21.0，内存 better-sqlite3。基线为 N4-I 主线 df813df（在原代码上运行相同脚本），候选为 N4-J。脚本为 `pnpm performance:chinese-search`，输出逐查询 TP/FP/FN、结果和 P95。

| Precision | 100% | 95.45% |

新增误匹配是 AI 模型查询命中 Sand.ai 视频生成模型标题，保留原先初标，不为适配结果修改标签。基线与候选 P95 为两次本地运行的观察值，样本少且无多轮误差估计，不声称性能提升。该语料为助手初标且非独立保留集，不能外推生产精确率。
