## F1：Node API 基准切片（计划与验收）

### 范围

- 增加仅供本地基准使用的 30 个静态插件来源。插件不加入正式目录，不访问网络，也不默认启用。
- 基准命令构建并启动 Node 生产产物。服务使用临时工作目录、临时 SQLite 数据和临时插件存储；所有临时资源在退出时清理。
- 基准构建设置 `LATESTNEWS_SKIP_FAVICON_FETCH=true`，沿用仓库已有图标，不向图标服务发出公网请求。
- 测量单源 API 和 10/30 个来源批量 API 的全命中、全未命中、部分未命中和旧缓存路径。默认每种场景发送 1,000 个请求，并记录预热次数。
- 报告记录 p50/p95/p99、吞吐、错误率、解码后响应大小、缓存响应状态、服务启动时间、服务进程 CPU/RSS、操作系统、处理器、Node/pnpm 版本和 Git 提交。
- 服务进程 CPU/RSS 每 250 ms 采样一次，时间范围从进程启动到停止，包含启动、缓存预热和全部 API 场景；这些资源指标不按 API 场景拆分。
- 目标地址只允许 `localhost`、`127.0.0.1` 或 `::1`。运行不得访问公网，也不得读取用户凭据。

### 验收

- 小样本冒烟可启动生产 Node 服务，验证全部缓存状态场景，并自动清理子进程、临时数据库和插件目录。
- 完整命令对每种场景执行 1,000 个样本；响应必须有效，缓存状态可识别，错误率与响应字节数有报告。
- 基准 JSON 默认写入被 Git 忽略的 `.data/performance/`，不把本机结果混入应用发布产物。
- 插件样例通过清单验证和离线回放；项目 lint、Node/Web 类型检查及相关测试通过。

### 验证命令

`pnpm crawler validate crawler-platform/examples/performance`、`pnpm crawler test crawler-platform/examples/performance`、`pnpm performance:baseline -- --samples 10 --concurrency 2`、`pnpm lint:check`、`pnpm typecheck`、`pnpm typecheck:electron`、`pnpm test --run`、`git diff --check`。

## F1：缓存状态基准扩展（已完成）

### 范围

- 扩展同一 Node API 基准，增加单源、10 源和 30 源冷缓存未命中、30 源部分命中和 30 源旧缓存场景。
- 只操作基准临时目录中的 SQLite `cache` 表。每轮并发请求前清除指定来源缓存；旧缓存场景只调整这些临时记录的时间戳。
- 对冷缓存要求所有来源返回 `success`；部分命中要求命中与新采集各占一半；旧缓存要求所有来源返回 `stale-cache`。任何状态不符或 API 错误都使基准失败。
- 保留缓存命中基线和默认 1,000 样本。记录每个场景的缓存状态分布，不把预备和清理操作计入 API 延迟。

## F2-A：服务端采集队列边界（已完成）

### 范围

- `server/utils/source-fetch.ts` 为内置适配器和 Node 插件源增加共用采集队列。
- 默认最多同时执行 8 个来源任务，最多等待 100 个任务。排队超过 8 秒的任务返回 `TIMEOUT`；队列已满的任务返回 `QUEUE_FULL`。
- 同一来源在排队或执行期间继续复用同一个 Promise，避免并发请求重复采集。队列错误进入既有来源失败和批量诊断路径，不改变 API 响应结构。
- 本切片只限制任务总数和排队等待。它不声明按目标主机限流，也不提前中止无法接收 `AbortSignal` 的旧适配器；这两项需要独立验收。

### 验收与验证

- 定向测试覆盖同源请求合并、并发上限、队列溢出和排队超时。
- `pnpm test --run` 通过 63 个测试文件、293 个用例；`pnpm lint:check`、`pnpm typecheck`、`pnpm typecheck:electron`、`pnpm test:electron` 和 `pnpm build` 通过。
- 构建仍会输出已有 Zod 注释和图标下载超时警告；构建成功，默认图标回退行为保持不变。

### 回退边界

删除 `createSourceFetcher` 的队列选项和实例化即可恢复原有的直接采集路径。该切片不修改来源 ID、缓存格式、插件包格式或客户端协议。
