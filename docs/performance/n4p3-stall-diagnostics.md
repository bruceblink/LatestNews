# N4-P3 异常停顿诊断与长测（2026-11-26）

基线：749c91b（#39）。本轮只扩展本地性能实验工具，不修改 server/、D1、数据库 schema、生产配置或生产调度。

## 诊断方法

- 原 90 秒实验最终数据正确，但 45/90 写和 77/180 读实际完成，出现约 13.5 秒停顿；历史样本没有独立宿主探针，无法归因。
- 新工具在 250ms 以上的 SQL prepare/执行、事务及读写/维护操作中记录起始时刻、墙钟耗时、进程 CPU 耗时和固定操作分类（不保存 SQL 文本/参数、源内容或秘密）。最终工具还记录快速 SQL 失败的安全错误码及单个慢事务的 acquire/callback/tail；每个采样集合最多保留 128 个最长事件并计数，错误码计数可能包含语句和外层事务两次观测，不代表唯一失败次数。CPU 是整个进程的 user+system，不是 SQL 专属 CPU；非 CPU 时间不等于精确锁等待。
- 独立第四个进程不连接数据库，每约 250ms 记录定时器迟滞、墙钟/CPU 时间和 Linux /proc/pressure、/sys/fs/cgroup/*.pressure 累计计数差值；/proc/stat iowait/steal 为 tick。cgroup 路径在当前隔离环境为 root，不能认为这些计数归属于某个 SQLite 操作。缺少权限/平台支持则省略指标；不是 0。探针只覆盖 offered load 窗口，不覆盖最终排空/校验；迟滞不含上一次读取压力文件的时间。采样增加少量测量开销，不能直接与未插桩的旧样本作严格因果对照。
- --journal delete|wal 仅作用于脚本自己创建的临时数据库。所有工作连接 synchronous=FULL；既有 busy_timeout 5000ms；不改部署默认日志模式。DELETE 与 WAL 依次执行，未随机化，不并行运行其他性能实验。
- 同机独立维护/写/读进程；初始 100k，页 100，30 条快照每秒 1 个、检索每秒 2 次，90 秒内每 30 秒尝试重建。两轮均严格检查所有预定操作及最终文章、来源、缓存、FTS 和持久审核，跳过不算成功。

## 正式 1800 秒

实际启动 DELETE / FULL / 100k / page=100、1800 秒、每 300 秒尝试重建、1 快照/s、2 读/s 的正式测试。前台工具连接约 2 分钟时传输中断，原进程仍持续运行；没有启动重复负载。工作进程运行约 30 分钟后退出。末段日志（UTC 05:34:03）出现一次 Article maintenance is unavailable 告警；最终父进程报错 `write worker exited: 0/null`，没有收到写入结果，也没有 RESULT 或最终逐条一致性结论。旧脚本清理临时库，无法事后重建计数。此次为已执行但无有效结果的验收尝试，不声称完成 1800/3600 操作或最终一致性通过。不能仅从退出码判断 IPC 丢失的具体原因。

## 修复长测结果交接

- IPC 只发送 ready 和 start 控制消息。读/写/host 子进程在退出前先写独立证据目录的 *.partial，再 rename 到最终 JSON；父进程在 close 且 exit=0 后读取结果。缺失/不完整/非法 JSON 均失败，不以退出码代替数据。
- 证据目录默认为新建的临时目录，启动时输出 EVIDENCE 路径；可用 --evidence-dir 指定一个不存在的新目录。目录独立于临时 SQLite 文件，后者仍在 finally 清理。维护循环结束后先发布 maintenance.json，再等待工作进程、核验数据及发布 result.json。发生后段失败时保留已发布证据；进程在首次发布前被杀不能保证保存全部样本。每次运行后按需清理证据目录。没有写入真实源站数据或凭据。
- 初版 5 项新增测试覆盖 PSI 解析/缺失指标、慢操作记录上限、CPU/墙钟测量、真实子进程 7200 条样本（超过 3 MB）的文件交接、缺失/partial/非法 JSON 拒绝。1k/3 秒真实进程 smoke 通过，读写样本与 result.json/stdout 一致。

修复后再执行一次同配置 90 秒 DELETE。五份证据文件均保存（host/write/read/maintenance/result），汇总 JSON 与 stdout 一致。89/90 写、178/180 读，跳过 1/2，无操作失败、维护不可用或锁超时；最终 100205 篇及映射、缓存一致，FTS verified，pending/untracked=0。恢复 27.206/33.255/25.310 秒，写 P95/P99 917.738/2856.086ms，读 P95/P99 432.621/980.857ms。该轮为 incomplete-load，不通过吞吐门槛。

最慢 journal 事务 2833.706ms、进程 CPU 2.623ms，BEGIN IMMEDIATE 获取耗时最大 2832.182ms，最长回调执行仅 4.768ms（所有 journal 事务取最大）。重叠的 12 个独立压力采样窗口 cgroup I/O full 总计 2077061us、CPU some 594us、memory full 1132463us。压力采样窗口包含部分邻接时间，不是该事务专属等待；独立心跳最大迟滞 5ms，说明本轮慢 SQL 不伴随同量级观察进程迟滞。此为实测锁获取延迟和共享存储/内存压力相关证据，不是原 13.5 秒停顿的根因证明。未改变默认 SQLite 或 D1 参数。

## 最终工具准入加固与 60 秒复测

- 每个子进程的结果先核对角色、速率、准确的预定槽位数、跳过数、样本序号单调且不重复及时间字段。计时器唤醒后再次检查过期槽位；不以事后补发掩盖未完成的负载。
- 分别判定最终数据正确性、操作结果、预定负载、重建周期及停止输入后的排空。最终排空循环同样记录全部维护状态和事务；最终数据校验失败保留统计并返回失败，不能只凭最终数据一致或进程退出 0 判通过。
- 真实 SQLite 约束失败测试验证安全错误码与事务 acquire/callback/tail 记录；不复制原始 SQL、参数或异常消息。完整结果文件不是断电持久化保证，仍依赖文件系统；子进程在发布前异常终止时只能保留已写入的证据。
- 100k/100 键、1 写/s、2 读/s、每 30 秒尝试重建、60 秒，最终工具逐项核对负载及两个计划周期，顺序执行 DELETE 后 WAL。
