# 新闻源爬虫插件化架构排期

日期：2026-10-27。当前分支：`main`。

本项把“新闻源爬虫插件化”从条件性远期事项提升为近期开发主线，先收口协议和宿主边界，再等待外部接入证据。公网采样不属于本切片，继续延后；所有验收使用本地 fixture、进程夹具和离线 API。

## 当前阶段：F6-A 协议与宿主边界收口

F6-A 的目标是让插件可以在 Node 与 Electron 宿主间复用同一份清单和 bundle，并且每个宿主对网络、执行时间和输出规模有一致的可验证上限。

已落地的第一片：

- `manifest.limits` 固定执行、请求、响应、条数和输出字节预算。旧清单不写 `limits` 时使用兼容默认值。
- 网络 broker 把 HTTPS origin、凭据头、方法、请求头和请求体大小检查集中到 SDK；Node 子进程宿主和本地注册表使用同一套权限判断。
- 进程宿主按清单限制任务期限、单次响应、单次运行累计响应、请求次数，并在结果边界再次限制条数和总字节数。
- worker 在发送 IPC 前先执行请求次数、请求头和请求体预算，宿主再执行一次边界校验；worker 失败码会原样映射回宿主错误。
- 预算越界返回固定的 `RESOURCE_LIMIT` 错误；凭据头和 `Set-Cookie` 不穿过插件边界；离线测试覆盖请求次数、请求体、头部和跨宿主注册表路径。
- 示例插件清单和作者文档已经展示完整预算，bundle 会写入规范化清单。

本阶段剩余工作按以下顺序执行：

1. 把清单预算、错误代码和 Node/Electron 同包行为加入持续集成的定向检查。
2. 为凭据引用、健康状态和重试策略补充协议草案，但不在插件中开放应用登录 Cookie、SyncHub key 或任意环境变量。
3. 记录一个本地 Docker/utility process 的资源验收报告，确认超时、超大响应、取消、进程退出和回退不会阻塞内置来源。

## 后续阶段与门槛

| 阶段 | 进入条件 | 产物 | 当前状态 |
| --- | --- | --- | --- |
| F6-A | F4 SDK、F5 动态目录和本地宿主可用 | 清单预算、共享权限检查、跨宿主离线验收 | 当前开发中 |
| F6-B | 至少两个需要独立发布的真实适配器，或外部维护者明确接入 | 两个独立插件、升级/回退和兼容报告 | 等待证据 |
| F6-C | F6-B 通过且有陌生代码需求 | 沙箱候选、发布者身份、签名和安装治理 | 未启动 |

F6-B 之前继续使用仓库内审查目录和版本化本地 CLI。当前不建设公开插件市场、远程任意代码执行、插件安装 UI 或自动下载第三方包。`trusted-js` 可用于操作者信任的适配器，但独立进程和网络 broker 不能证明陌生代码安全。

## 验收和回退

- 本地验收：manifest 校验、Node/Electron 同 bundle 输出一致、网络权限拒绝、资源预算拒绝、取消与进程退出。
- 集成验收：内置源在插件失败或回退时仍可读；动态来源目录、详情、批量和 Feed API 保持现有契约。
- 不执行公网采样，不把真实源站响应、线上部署或真实窗口结果作为本阶段通过条件。
- 若预算协议需要回退，删除 `limits` 的宿主执行和对应测试即可；旧清单仍能通过默认预算运行，不改变来源 ID、缓存和客户端 API。
