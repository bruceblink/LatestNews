# N3-G1：公开诊断错误安全边界（A09）

2026-11-26，基线 `7312eb30de6c5702fc5094b981caa1be4a8122fc`（#34）。用户要求延后 N2-D1，优先继续 N3-G1、N4-P1、N3-G2、N4-P2、N4-P3。N2-D1/A12 仍是开放 P0；N2-D2/D3 随依赖延后，不启用新同步能力或改变外部服务。

## 实现

- `shared/source-error.ts` 定义稳定的公开错误类别与固定消息。只识别已知 code、明确异常名称和 400–599 整数 HTTP 状态；旧消息仅识别固定文本与受限数字状态。不复制原始异常、cause、响应、请求 URL、头、堆栈或任意字符串，不执行 String(error)。未知失败统一为 UNKNOWN，长度有界。
- 源健康状态在写入内存前安全分类，持久化新事件和历史事件读取再次投影；公开 JSON 和文本诊断投影旧字段。保留状态、计数、时间、缓存降级、既有 v1 字段。旧数据不自动清理。
- 批量/洞察错误增加可选 code，保留 sourceId/message；单源、批量、Feed、健康、节点和洞察 HTTP 捕获边界新建安全错误，保留有效 HTTP 状态和本地固定验证消息，不转发原异常字段。节点与联邦本地健康摘要本身只投影计数。
- 采集、配置型来源初始化、来源健康事件、缓存路径的相关日志使用安全分类；两个 legacy 来源直接 console 错误路径亦改用安全分类。Electron 本地采集移除基于正则的原始消息输出，冷缓存失败的 IPC 异常也使用固定文本；成功清除最近失败文本。
- 不改变采集调度、历史索引状态机、D1 请求级隔离、SyncHub 或插件协议。受信插件内部的错误/IPC 仍可用于运行时控制；本轮不是整个应用的日志审计或第三方远端服务的安全修复。
